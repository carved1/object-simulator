# Reflection: Object Simulator

## Structs vs Classes

In Python, a class groups data and behavior, and the interpreter creates the object, stores the methods, and supplies the instance when a method is called. C has none of that machinery, so this program builds it by hand. The Character struct holds name, health, and level, plus function pointers for attack and take_damage. Those pointers are only addresses until character_init assigns them. That function copies the name with strncpy, null-terminates it, stores health and level, and points attack at character_attack and take_damage at character_take_damage. A call also needs an explicit self: hero.attack(&hero) looks up the stored function and passes the object's address. Python hides both steps. hero.attack() finds the bound function and inserts the instance as self, which is why a method is written as def attack(self). What this C code shows is that lookup and that argument made visible. The struct stores the function address, and the caller passes the object so the function can read and change its fields. Warrior and Mage constructors later overwrite the attack pointer, which is the same idea as overriding a method on a subclass.

## Inheritance Implementation

Inheritance here is composition. Warrior and Mage each start with a Character member named base, placed first so the derived object and its base share the same address. warrior_init calls character_init on that embedded base, sets strength, and replaces base.attack with warrior_attack. mage_init does the same for mana and mage_attack. A Warrior pointer can then be cast to Character and used wherever a Character is expected, and the specialized function casts it back to reach strength or mana. Python writes class Warrior(Character). The subclass inherits attributes and methods without an embedded base or any casts. super() calls the parent constructor, and overridden methods are resolved without storing function pointers or keeping the base as the first field. A wrong cast, or a base that is not first, breaks the C version. Python's syntax removes those layout rules from ordinary code.

## Understanding OOP Mechanics

party[i]->attack(party[i]) runs different code because each object stores its own function address. A plain Character points attack at character_attack. A Warrior points it at warrior_attack, and a Mage points it at mage_attack. The loop never checks the type. It follows the address in that struct, so one call site produces a basic attack, a sword swing, or a fireball. That is polymorphism: behavior depends on the object, not on an if statement at the call. C has no classes, but systems programmers still use this pattern because it is small and explicit. Drivers, file systems, and toolkits keep a struct of function pointers so new behavior can be added by filling in different functions without rewriting the callers. The programmer assigns the pointers, passes self, and keeps the layout valid. In return they control memory and share one interface across many implementations.
